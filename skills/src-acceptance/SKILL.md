# SRC 接收验收标准（提交前质量门）

> 接收方只认“可复现的真实危害”。以下每条都是会被退回的硬原因，提交前逐项核对。

## 一、必交材料（缺一退回）

1. **漏洞标题**：系统 + 功能 + 缺陷 + 影响，不写“疑似/可能存在”；
2. **目标**：完整 URL/Host/IP、端口、方法、参数；
3. **身份与前置**：匿名/普通用户/管理员、账号、Cookie/token、网络位置；
4. **复现步骤**：编号步骤，每步可执行；含请求原文（请求行+头+Cookie+body）；
5. **响应证据**：状态码、关键响应头、完整响应正文或数据集；
6. **危害证明**：读到多少条/哪些字段、写了什么测试对象并回读、权限差异、命令回显；
7. **数据量**：≥10 条去重记录或全量/总数；只给 1 条不接收；
8. **未脱敏**：目标数据原值；出现 `***`/`[redacted]`/`已脱敏`/打码即视为未拿到数据；
9. **复现命令**：curl/sqlmap/nuclei/python 可直接跑，注明预期输出特征；
10. **附件**：截图含 URL/关键字段；数据集 artifact id + sha256；流量 baseline/proof；
11. **验证时间**；12. **修复建议**；13. **未验证范围**（如有）。

## 二、按等级的接收门槛

| 等级 | 最低证据 |
|---|---|
| critical | 未授权/低门槛 RCE 或管理员接管；批量敏感数据（≥1000 条或全量+字段+样本）；资金/订单篡改可回读；命令回显 + 权限级别 |
| high | 越权读他人敏感数据（≥10 条或全量）、任意文件读/写证明、受限命令执行、后台管理员权限；两个身份对照 |
| medium | 需前置条件的越权/注入、含敏感字段的信息泄露、存储 XSS 影响管理员；有原始请求/响应 |
| low | 轻微信息泄露/配置问题；有可复现请求与影响说明 |

## 三、直接退回项（红线）

- 只有版本/banner/CVE 匹配，没有行为验证；
- 只有 1 条记录/1 张截图，没有总数/字段；
- 证据被 `***`、`[redacted]`、打码、覆写；
- 没有原始请求/响应，只有“返回成功/存在漏洞”的文字；
- 越权类只有一个身份，没有权限矩阵；
- 写类没有自建测试对象/回读/清理，或碰了生产数据；
- 复现命令跑不通或与实际证据不一致；
- 把“疑似/可能/理论上”写成已确认；
- 报告内容与 finding 证据/流量对不上。

## 四、补齐动作（按缺口）

- 缺数据量 → 分页/时间窗/导出接口取全量，统计总数与字段，保存原始响应；
- 缺权限 → 用匿名/A/B/管理员四个身份对同一接口做矩阵；
- 缺写证明 → 建唯一 marker 测试对象，写入后回读，记录前后值并清理；
- 缺命令执行 → 用 `id`/`whoami`/`hostname` + 读敏感文件前几行证明权限；
- 缺复现 → 把实际执行的命令原样贴出，标注预期输出；
- 缺附件 → `save_evidence` 登记数据集/截图，记录 sha256 与 artifact id；
- 缺流量 → `traffic_refs` 绑定 baseline 与 proof。

## 五、提交前自检

- [ ] `evidence_check` 返回 `src_ready=true`，或 missing 已逐条解释
- [ ] 每条漏洞都有“原始请求/响应 + 复现命令 + 危害证明”
- [ ] 数据类有总数/字段/未脱敏样本；越权类有身份矩阵；写类有回读
- [ ] 报告与 finding 证据、traffic、artifact 一致
- [ ] 未验证范围如实写明，没有把未做写成已确认
