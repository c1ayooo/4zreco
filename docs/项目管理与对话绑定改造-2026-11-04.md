# 项目管理与对话绑定改造（2026-11-04）

> 移植自 4zrec v0.5.x 的「项目主轴」能力，按本项目需要裁剪：**只做项目管理、快速切换项目、对话页绑定任务&项目，不接资产围栏**。
> 参考实现：`~/4zrec` 提交 62b1f9e（项目主轴）、42b85c7（UX）、d47979f/v0.5.2（对话关联任务、项目切换器）。

## 0. 范围裁定（明确不做的）

| 4zrec 原能力 | 本项目 | 原因 |
|---|---|---|
| `assets.project_id` / `assets.authz` 状态机（approved/pending/rejected 只升不降） | **不接** | 资产授权是围栏的状态机基础；围栏不出范围 |
| 执行侧围栏 guard/fence（命令字面目标提取→范围判定→合成 ask 审批） | **不接** | guard 已有 egress/tarpit/三层拦截，独立演进 |
| 发现侧/注册侧闸门（insert_assets 打 pending、CheckAssetsIntercept 拒绑） | **不接** | 同上 |
| 范围候选生成（从资产反推/LLM 建议） | **不接** | 依赖资产归属；范围手工录入即可 |
| 审批中心 / 项目级 API Key | **不接** | 围栏配套 |

接进来的核心语义（与 4zrec 对齐）：

- **项目 = 任务的归属主轴**：`tasks.project_id`、`conversations.project_id`、`conversations.task_id`。
- **项目范围 = 组织定义**：`project_scope` 记录项目覆盖哪些目标（域名/网段/ICP/关键词），用于项目详情展示与项目卡片信息，**不做任何执行侧强制**。
- **任务挂项目时范围种子**：`project_scope`（domain/ip/cidr）种成本任务初始 `task_scope`（`source='project'`），规划器第一轮就有范围可依、覆盖度分母完整——这是规划上下文，不是闸门（原 4zrec 语义保留，与围栏无关）。
- **对话绑定任务**：`task_id` 是纯引用（任务删除置空）；绑定任务时把会话项目对齐到任务所属项目。

## 1. 数据库（schema.sql，幂等迁移）

新增 §（放在 §D 任务层之后、§I 对话之前均可，集中在 task_scope 段落后）：

```sql
-- 项目（任务/对话的归属主轴）。4zrec 同款收窄版：不挂 authz/资产归属。
CREATE TABLE IF NOT EXISTS projects (
    id          BIGSERIAL PRIMARY KEY,
    name        TEXT NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    status      TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active','archived')),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
DROP TRIGGER IF EXISTS trg_projects_upd ON projects;
CREATE TRIGGER trg_projects_upd BEFORE UPDATE ON projects
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();

-- 项目授权范围：结构镜像 company_scope（解析复用 ParseScopeInput），仅作组织定义。
CREATE TABLE IF NOT EXISTS project_scope (
    id         BIGSERIAL PRIMARY KEY,
    project_id BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    kind       TEXT NOT NULL CHECK (kind IN ('domain','ip','cidr','icp','keyword')),
    domain     TEXT, net CIDR, value TEXT,
    raw        TEXT NOT NULL, reason TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uq_project_scope_domain UNIQUE (project_id, domain),
    CONSTRAINT uq_project_scope_net    UNIQUE (project_id, net),
    CONSTRAINT ck_project_scope_payload CHECK ( ...同 company_scope... )
);
-- icp/keyword 唯一 + 索引，同 company_scope 的 uq_sv2_value/idx_sv2_company。

-- 任务/对话挂项目；项目删除一律置空（不连带删除）。
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS project_id BIGINT REFERENCES projects(id) ON DELETE SET NULL;
ALTER TABLE conversations ADD COLUMN IF NOT EXISTS project_id BIGINT REFERENCES projects(id) ON DELETE SET NULL;
ALTER TABLE conversations ADD COLUMN IF NOT EXISTS task_id BIGINT REFERENCES tasks(id) ON DELETE SET NULL;
CREATE INDEX IF NOT EXISTS idx_tasks_project ON tasks(project_id) WHERE project_id IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_conversations_project ON conversations(project_id) WHERE project_id IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_conversations_task ON conversations(task_id) WHERE task_id IS NOT NULL;

-- task_scope.source 扩 'project'（任务挂项目时的种子来源）。
ALTER TABLE task_scope DROP CONSTRAINT IF EXISTS task_scope_source_check;
ALTER TABLE task_scope ADD CONSTRAINT task_scope_source_check
    CHECK (source IN ('auto','agent','manual','project'));
```

> 注意：本项目 task_scope 的 source CHECK 是内联列约束（4zrec 是表级），名称按实际执行 `ALTER` 后回查确认；若建表时未命名，用 `DROP CONSTRAINT IF EXISTS task_scope_source_check` 前先在 psql 验证约束名。

## 3. 前端

- **`ProjectRow`**（4zrec 原样适配）：Popover 挂载/更换/取消挂载项目；列表项显示「任务 N · 范围 M 条」；底部「新建项目」链接。

- 任务列表行：项目徽标（链接 `/function/projects`）；`?project_id=N` 深链切换全局 store 并按项目过滤（`projectId=0` 显示全部）。
