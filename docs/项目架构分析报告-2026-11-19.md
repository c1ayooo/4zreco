## 0. 执行摘要

4zreco 是一个 **AI 自主渗透测试平台**，代码声明的适用范围是“仅供授权测试”；README 的免责条款进一步限制为个人学习、代码研究与本地隔离验证，禁止对线上系统发起实际测试（`README.md:380-386`，`AGENTS.md:16`）。本分析只做静态代码与配置审查，不对任何外部目标发起扫描、利用、登录爆破或回连。

架构上，项目是 **Go 单体后端 + Next.js 静态导出前端 + PostgreSQL 唯一业务存储**：

- 三个可执行入口：`cmd/4zreco`（主服务，HTTP 默认 `:8787`、流量代理默认 `127.0.0.1:8788`），`cmd/4zreco-hostd`（特权助手），`cmd/4zreco-maint`（离线维护工具）。证据：`cmd/4zreco/main.go:49-54`，`cmd/4zreco-hostd/main.go:1-11`，`cmd/4zreco-maint/main.go:1-15`。
- `internal/` 有 32 个包、826 个跟踪文件，其中 799 个 Go 文件；`git ls-files internal/* | awk ...` 统计结果。
- `go.mod` 使用 Go `1.26.3`，直接依赖 28 个（`go.mod:3,5-34`）；eino 锁定 `v0.9.21`（`go.mod:12`），并由 `scripts/check-eino-boundary.sh:20,98-108` 机检。
- 前端为 Next.js `^16.2.9`、React `^19.2.7`、TypeScript `^5.9.3`、Tailwind `^4.1.5`、Biome `^2.5.1`（`web/package.json:42,45,47,65,76,79`）；共 34 个 `page.tsx` 路由页面（`git ls-files web/src/app ... | wc -l`）。
- 后端通过 `net/http` 集中注册 API；`internal/server/server.go:784-1205` 是 HTTP 入口，`internal/server` 下 `HandleFunc` 静态出现 352 次（其中 `server.go` 329 次），该数字是出现次数，不等同于唯一路由数。

核心架构边界清晰：**双图与 planner/worker 调度留在 engine，eino 只做 Agent 循环、工具面和中断/检查点骨架，拦截判定保持纯 Go**。该边界由 `AGENTS.md:154-174` 与 `scripts/check-eino-boundary.sh` 定义和部分机检。

本次确认的首要工程风险不是业务代码缺陷，而是 **CI 门禁覆盖缺口**：`.github/workflows/ci.yml:4-8` 仅在 `push.branches: [main]` 与 `pull_request` 触发，而仓库基线是 `master`；`AGENTS.md:95-96` 也记录直推 master 不触发任何 workflow。其他高价值线索包括文档口径不一致、入口注释陈旧、测试门控可能假绿、前端 lint 未入门禁，以及装配指纹三分量未接真值。历史体检工单大多已有完成记录，不能重新包装为当前缺陷。

由于任务边界明确要求“只分析，不修改代码”，本节点 **未执行** `go build ./...`、`go vet ./...`、全量测试、架构门禁脚本、前端构建或真实运行验证。因此本文不声称任何构建/测试通过。

       │ 工具调用                 ▲ 模型调用/中断恢复
       ▼                          │
guard / intercept / 纯 Go 判定包 ──┘
       │
       ▼
internal/db（PostgreSQL 唯一业务存储：双图、trace、审批三表、checkpoint、证据引用）

       ▼

## 5. 核心功能与调用关系

### 5.1 进程启动链

`cmd/4zreco/main.go:49` `run()` → `:94` `server.NewManager` → `:108` `config.NewPaths` → `:114` `server.New` → `:117` `srv.Handler()` → `:123` `httpSrv.ListenAndServe()`。

`NewManager` 在 `internal/server/manager.go:683-707` 连接 PostgreSQL，并按 `proxyAddr` 启动流量代理；`:684` 明确“PostgreSQL is required (it is the single data source)”。

### 5.2 HTTP 接入与鉴权链

`internal/server/server.go:784` `Handler()` 集中注册路由；`:818` 注册 `POST /api/tasks`；`:1197-1204` 的分层为：

1. `securityHeaders(s.requireAuth(mux))` 包住 `/api/`；
2. 根 mux 把 `/api/` 交给 API、其余路径交给 `webuiHandler()`；
3. 最外层 `requireBasicAuth` 同时保护 API 与静态壳。

JWT 豁免名单在 `internal/server/auth.go:361-373`（`/api/auth/*`、`/api/health`、`/api/basic-auth/check`、企微回调等）；Basic 门在 `internal/server/basic_auth.go:141`。无 `embedui` 时静态壳由 `internal/server/webui_stub.go:14-17` 返回 404；有标签时由 `internal/server/webui_embed.go:24-54` 提供静态文件与 SPA 兜底。

### 5.3 任务创建与准入链

`POST /api/tasks`（`server.go:818`）→ `createTask`（`server.go:1771`）→ `Manager.CreateTaskWithOptions`（`server.go:1867`，实现 `manager.go:1553`）→ `launchTask`（`server.go:1899`）。编排 `spawn_task` 走同一入口（`internal/server/orchestration.go:331,353`）。

`launchTask`（`internal/server/goals.go:29-41`）→ `admitTask`（`:116-118`，单一准入路径）→ `startAdmittedTask`（`:267-291`）。bootstrap 模式启动 goroutine 调用 `startTaskEngine`（`:48-83`），其中 `createGoals`（`:300-317`）调用 `agent.DecomposeGoalsWithProvider`（`internal/agent/goals.go:113`）做第 0 轮 LLM 拆解，最后 `Engine.Run`（`internal/server/engine.go:772`）。目标拆解带 5 分钟墙钟（`goals.go:43-68`），超时回退为原始目标，避免任务永久卡在 created。

### 5.4 自主推进闭环

1. 信号：图变更/发现/完成通过 `Task.Notify`、`NotifyDone`、`NotifyFinding` 非阻塞唤醒（`internal/server/manager.go:2576,2587,2598`）；心跳由 `engine.go:962-966` 提供。
2. 防抖：`engine.go:991-1000` 在 `plannerLoop` 内 drain `t.notify`，合并突发变更；防抖初值 800ms（静态配置见 `engine.go:432`，由需求基线核实）。
3. 规划：planner 产出 0..4 个意图，工具入口 `AddIntent`（`internal/agent/tools.go:1440`），DB 实现 `internal/db/exploration.go:273`。
