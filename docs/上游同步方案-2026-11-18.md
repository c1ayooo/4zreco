## U1 预置凭据登录熔断(v0.4.82,直接移植)

- **源**:`git show 65be1d6 --stat`;上游 `agent/login_breaker.go`(+测试)、
  `sessionLogin` 前置熔断检查与 401/403 结果记账。
- **意图**:密码过期/改密后,多 worker 对同一预置凭据反复 401/403 会锁死客户账号。
  按 `asset_id+auth_index` 维度对预置凭据做 **2 次失败熔断 30 分钟**:熔断期本地直接拒绝
  (不发请求),超时后 half-open 放行一次试探,成功即自愈。
- **落点**:`internal/agent/login_breaker.go`(新,纯 Go 状态机)+
  `internal/agent/tools_http.go:648 sessionLogin` 接线(调用前查熔断、结果后记账)。
- **改写点**:状态存储形态照抄上游(内存 map 即可,单进程单体,无需 db);熔断参数
  (2 次/30min)可先常量,不做 settings 键;仅作用于**预置凭据**,不拦用户手填的
  run 级凭据。
- **本地差异(G3 折中方案,`b35a79b7`)**:失败计数按**账号维度跨任务共享**——状态键
  只由 `asset_id+auth_index` 构成(去掉了初版实现里的 taskID 分量),避免「N 个任务
  各打 2 次」把客户账号锁死;同时在 `session_login` 增加可选入参 `breaker_probe`
  (默认 false),熔断期内**单个任务**可显式申请一次试探放行,每任务每凭据仅一次;
  试探仍失败则立即重新熔断且失败计数不回退,成功则整条状态(含豁免记录)删除。
- **测试**:状态机表驱动单测(失败计数→熔断→本地拒绝→half-open→成功自愈/失败续熔)、
  跨任务共享计数(`TestLoginBreakerSharedAcrossTasks`)、任务级一次性豁免
  (`TestLoginBreakerTaskProbe`:拒绝→申请放行→同日再申请拒绝→他任务仍可申请→
  试探失败续熔→成功整条复位)。

## U2 ExecuteExtraTool 守卫解包(v0.4.80 #21.3,直接移植,P0)

- **源**:`git show 3d5c9b8`(v0.4.80)中 guard unwrap 相关提交;搜 `unwrap`。
- **意图**:模型经 `ExecuteExtraTool` 调用延迟注册的工具时,拦截链路(规则匹配、LLM
  judge、审计 trace)看到的是**包装器名 + 整段 JSON 参数**——按真实工具名(如
  `zombie_weak_passwd`)和 shell 命令内容写的拦截规则全部漏判,tool_scope 与 Bash 类
  规则可被绕过。解包后按内层 `tool_name + params` 走判定。
- **落点**:`internal/acllm/toolgate.go`(+`middleware.go`)——把内层工具名/参数解出后
  再递给 intercept/guard 判定;审计与 trace 同步记**真实工具名**。本地 ExecuteExtraTool
  概念在 acllm/kernel(askernel/session.go)已有,只缺判定前解包。
- **红线自查**:解包做在 acllm 层,`internal/guard`/`internal/intercept` 本体不引 eino
  (R4 合规);判定逻辑仍是普通 Go 包,eino 挂点只留一行调用(骨架/器官分层)。
- **测试**:回归两形态——直接调用 deferred 强动作工具 vs 经 ExecuteExtraTool 包装的同名
  工具+同参,断言规则命中与审计记录(真实工具名、内层参数)完全一致。
- **本地差异**:解包范围限 **deferred 集**内的内层工具(`unwrapDeferredCall` 的
  `deferred[name]` 判定)。非 deferred 内层不解包:生产路径 `server/assembly.go` 的
  unlock 集恒非 nil,包装器自身会以「not unlocked」拒绝,不存在漏判面;该设计由
  `TestGateExecuteExtraToolNonDeferredStaysWrapper` 固化。上游文档写的「包装内层 bash」
  在本地不适用(bash 类工具不是 deferred),不要据此判定缺口。
