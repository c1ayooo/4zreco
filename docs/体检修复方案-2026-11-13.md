# 4zreco 体检问题修复方案（2026-11-13）

> 来源：同日项目架构分析报告（会话产出）§4 的工单化。只收编报告确认的问题与低风险优化；
> 所有落点行号以 2026-11-13 master `f9865b9` 工作区为准，实施时以实际代码为准。

## 决策

- **D1 凭据打码（F3）**：采用 §5.5 既定纪律与 zombie/proton 先例（`tools_zombie_proton.go:439-452`
  输出打码）——观测面（audit trace / activity 的 tool_use 记录）对敏感字段打码，执行面不动。
- **D2 追留清理（O2）**：`server_logs` 默认 30 天启用；`llm_records` 默认关闭（录制数据可能需
  长期保留，一个 settings 键可开启）；审批三表（intercept_pending/decisions/executions）有
  append-only 触发器禁删，**永不纳入**清理。
- **D3 交付方式**：全部改动留在工作区，**不做 git commit**；由用户审阅后自行提交。
- **D4 db 默认超时（O4）**：保守 30s，只覆盖「无 ctx 参数」的核心路径；schema 迁移的 advisory
  lock 长事务路径不加（迁移本来就慢）。

## 明确不做（deferred，与理由）

| 项 | 理由 |
|---|---|
| server.go 拆分 / goals.go 函数归位 | 纯组织性重构，冲突面大（goals.go 归位会撞 manager.go 并行改动），收益低于风险 |
| 三套 chat 流统一、工具清单组合化复用 | 大型重构，需要独立设计轮 |
| SWR/react-query 引入、tasks/page.tsx 拆分、api.ts/types.ts 拆分 | 前端架构级改造 |
| JWT httpOnly cookie、SSE token 出 URL | 认证架构变更，涉及后端 SSE 鉴权通道改造 |
| v_intercept trigram 索引 | 视图 ILIKE 无索引可建（需物化或改查询），审批表当前行数小，观察 |
| noa 开关清理、Server.Close 空实现 | 均为文档明示的取舍/回退桩，动它需要产品决策 |
