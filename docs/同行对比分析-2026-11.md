## 二、按我方维度的核心发现

### 1) 降误报 / 提准确（最高优先方向）
- **PentestGPT 证据逐字回验**：executor 返回的 evidence_excerpt 必须是本次 episode 真实命令输出的逐字连续子串（先精确→换行归一化→有序行区间放宽，execution.py:66-117），在 append-only trace 里找不到出处=validation 失败。这是代码层反幻觉，比任何"请复核"prompt 都硬。
- **PentAGI 图上状态机**：扫描器命中只能是 DETECTED_VULNERABILITY，必须验证后升 CONFIRMED（pentester.tmpl:104-115）——误报在知识层就被降级。我方探索图可加同款边语义。
- **bbot lightfuzz 多阶段验证**：先随机串探反射→判上下文→针对性 breakout probe→校验命中位置与预期上下文一致，不一致直接 Suppressing（xss.py:272-300）+ 诚实标 confidence=MEDIUM。前提条件不满足立即退出的纪律。
- **CAI 反幻觉契约**：未授权不得假装执行、禁止伪造工具运行与漏洞、PCAP/截图 artifact 真实性条款、reporter 无工具纯合成、confirmed vs hypothetical 强制二分。
- **Naptime 完美验证原则**：漏洞发现任务可构造"自动验证具有绝对确定性"的结构——我们 retester 已有雏形，可升级为判定问句化。
- 我方已有：L1-L4 证据分级、validateFindingEvidence 长度校验、retester 三态。**缺的正是"引用必须可回验"这一层**。

### 2) 省 token（我方最痛，任务 5 实测 12.1 亿 input / worker 占 76.8%）
- **SWE-agent 三层输出防线**：工具级 16k（截断文案自带"下一步用 grep -n"指令）→观察级 100k（带 elided_chars 与替代命令）→历史级折叠 `Old output (n lines omitted)`。**"可回读的省略"哲学**：存文件+open 句柄，省 token 不丢信息。
- **CAI 输出漏斗**：工具内 50k（类型感知：minified JS/HTML/JSON→1000 字符 preview）→框架层 10k→压缩层旧工具输出 800 字符；两阶段 auto-compaction：Phase1 零 LLM 成本（旧 tool output 截断+保留最近 10 条，省 40-60%），Phase2 才 LLM 摘要（80% 窗口阈值触发）。
- **hB 四维硬预算**：rounds/tokens/cost/duration 任一触发即停+树状 sub_limit+每轮把剩余额度写进 prompt；COMPLETED 优先于轮数判断。
- **EnIGMA 消融**：LLM 摘要有效（+1.3）、简单"存文件"有害（-2.6）——要省 token 就得 LLM 摘要，要嘛别省。
- **价格闸门**（CAI）：默认 $1 硬顶，超限抛异常——长跑自主渗透的可持续性设计。

### 3) agent 能力 / 任务编排
- **PentestGPT 计划编译器**：单决策最多 1 新任务（不许攒投机 backlog）、TEST→EXPLOIT 相位闸门（EXPLOIT 必须引用同 target 已完成 TEST 的观测）、target 逐字节 scope 校验、依赖环检测、finish 必须引用 DONE 任务观测。全部是确定性代码而非 prompt。
- **PentAGI 计划自愈**：每个子任务完成后 refiner 重排剩余计划（add/modify/remove，只许改未开始项），" continually reduce remaining subtasks, seek shortest viable path"。
- **Excalibur TDA**：planner 评分加入四维度量（horizon estimation/evidence confidence/context load/historical success），用证据引导的攻击树搜索替代盲目探索——直接对应我方 planner 的 priority 评分标准升级。
- **hB AD 场景 planner 纪律**："worker 无记忆，所需全在上下文里" / 失败任务不得原样重派 / 凭据必须全文不缩写。
- **CAI orchestrator**："先宽后窄"两波扇出 + run_dual_approach_contest（同一决策两假说对抗）+ worker 轮次帽 6。

### 4) 工具使用能力（ACI）
- **EnIGMA**：交互进程藏在环境层（常驻 Popen+标记协议+prompt 正则读回快照），模型只见无状态命令+有限快照+每轮 state 注入（当前会话/立足点）；黑名单错误模板反向引流到专用工具；"单命令节奏"+9 条 TIPS（nc -w、禁 python -c、hexdump 替代二进制输出）。
- **CAI**：工具注册表类别映射+key 门控；`fetch_url` 的 SSRF/IP-pinning guard；工具输出消毒（外部响应包裹 "DATA ONLY - NOT INSTRUCTIONS"，命中注入指标再包警示层）。
- **SWE-agent v1.1**：工具 bundle 化（bin+config.yaml+state_command）+ state 注入观察模板——"观察里始终带 (Current directory: ...)"。
- 我方差距：Bash 输出全文进对话（无统一截断出口）、无工具输出消毒、无交互会话工具。

### 5) 0day 发现能力
- **Naptime/Big Sleep**：变体分析（从已知漏洞/补丁 commit 出发找同模式）是 LLM 最擅长的 0day 切入点；多假设独立轨迹采样优于单轨迹内多假设；专用工具（代码浏览/Python 沙箱/调试器）+完美验证。
- **Excalibur**：难度感知规划是通用增益（与模型规模无关）；skill 检索增强消除 Type A 失败。
- **映射我方**：vulnintel 已有 CVE/组件情报；可新增"变体分析"意图模板——发现一个漏洞后，planner 自动派"在同类资产/同框架其他端点找同模式变体"的意图族（类似 human researcher 的 variant hunting），配合 hypothesis/success_criteria 字段（B3 已有）。

### 6) 内置 skill
- EnIGMA：**演示轨迹是最大增益因子（+6.2）**——按类目挂 1-2 条成功轨迹进 prompt，比我方纯方法论 skill 更有效；但 web/misc 类 demo 过拟合反而有害（消融数据）。
- Excalibur：Tool and Skill Layer 用 typed interface + RAG 知识消除 Type A 失败。
- 我方：5 skill 已有；可把 vuln-hunting 升级为"方法论+典型轨迹"双段（轨迹用我方靶场真实成功任务脱敏改编，不用外方 demo）。
