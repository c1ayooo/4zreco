## 0. 背景与总策略

4zreco 与 ARTEX（RuoJi6/ARTEX，module `github.com/Autumn-27/artex`）是同一原作者仓库
v0.3.15 的两个独立接手分支。ARTEX 保留旧布局（顶层包）与旧 norma 内核，独立演进到 0.3.29；
本仓库已完成 eino 内核迁移、`internal/` 收拢、HITL 双轨与全量更名。**两条线无共同 Git 祖先、
路径全部搬家，git merge/cherry-pick 不可行，只能按功能文件级移植**（先例：0.3.16 自 artex-c
移植蜜罐四件套）。

本方案覆盖三批（用户已选定）：

- **批次 A**：低成本直搬批（8 项）
- **批次 B**：审批三件套（脚本快照 / 审批旁问 / 审批检索）
- **批次 C**：漏洞归并（finding_cases）+ 任务情报（task_intelligence）

不移植：ARTEX `agent/request_limiter.go`（与本仓库 0.3.18 AIMD `adaptiverate.go` 功能重叠，
保留本地版）、英文 i18n 全站化（前端组件移植时剥离 i18n 调用、硬编码中文，与本仓库现状一致）、
Jev/System One 裁判与 `llmhttp/`（未选）。

### 通用改写规则（每个批次都适用）

| ARTEX 形态 | 4zreco 落点 |
|---|---|
| 顶层包 `agent/db/server/...` | `internal/agent/`、`internal/db/`、`internal/server/` |
| module `github.com/Autumn-27/artex` | `github.com/c1ayooo/4zreco` |
| `actool.Build` / `CoreTool` / `roTool` / `wrTool`（norma） | `internal/agent/tools.go` 的 `ToolSet` 构造器 + `readTool`/`writeTool`（纯读必须用 readTool，见 AGENTS.md §4） |
| 工具注册 server 层 + tools 表 seed | ToolSet 构造器 → 加入 WorkerTools/PlannerTools/MainAgentTools 三张清单 → `toolcatalog.go BuiltinToolSeeds()` 自动播种（**实现了必须注册**，AGENTS.md §4 红线） |
| `llm.Provider.Complete/Stream`（norma） | `internal/llmpool` 的 `Pool.Complete/Stream`（pool.go:130/:82）；单轮 judge 范式参考 `internal/server/intercept.go:198 oneCompletion` |
| settings 键常量分散定义 | 沿用本地惯例：消费方定义常量 + 读取时给默认值（无集中注册表） |
| 前端 i18n（`web/src/i18n/*`） | 剥离翻译调用，硬编码中文 |
| 品牌字符串（ARTEX/Artex） | 4zreco/ZRECO（localStorage/cookie 键同步改） |
| `agent.Abort*` 取消 sentinel | `internal/agent/cancelcause.go` 补对应常量 |

每个批次完成后的验证门槛（全跑）：`go build ./...`、`go vet ./...`、
`bash scripts/check-eino-boundary.sh`、真 PG `go test -p 1 ./... -count=1`（先 DROP/CREATE
`4zreco_ci`，见 AGENTS.md §1）、`cd web && npx tsc --noEmit`、`NEXT_EXPORT=1 npx next build`。

    重算」对齐。
- **测试**：判定函数表驱动（暂停不计时/复活重计/达标即不收场/并发临界不误停）+ PG 门控。

evidence 附录合并，db/finding_traffic.go:397-438）；ARTEX **没有**写时去重，finding_cases
是**后置 LLM 语义归并**（独立 findings 行 → reporter 按候选证据判定同一缺陷 → 建文件夹）。
两者正交、可共存：写时去重挡住完全重复，归并体系处理「同一缺陷的变体上报」。不删本地 dedup。

- **schema（7 表 + 2 触发器，幂等直搬 A/db/schema.sql:1480-1618）**：
  `finding_cases`、`finding_case_members`（finding_id PK）、`finding_case_events`、

## 5. 风险与已知取舍

1. **append-only 与 FK**：审批旁问的 `approval_id` FK 指向禁 DELETE 的 intercept_pending，
   CASCADE 永不触发（可接受，注明即可）；finding_case_suggestions 引用 findings（可删），
   anchor 重锚触发器随迁必须一并落地，否则删 finding 会级联炸建议组。
2. **advisory lock 常量空间**：C1 引入 `5100000000000000+taskID`，合并前 grep 全库确认无冲突。
3. **`mvdan.cc/sh` 新依赖**：进 go.mod 后跑一次全量测试确认无版本冲突；该库仅在
   intercept 判定路径使用，符合 R4（判定逻辑不感知 eino，纯 Go 包）。
4. **调度器单 tick**：计划任务挂进既有 5s tick，`fireTaskSchedules` 失败不得阻塞
   `reconcileConcurrency`（错误只落 schedule.last_error）。
5. **前端 i18n 剥离工作量**：A5/A7/C1/C2 组件源自带大量翻译键，逐个手工替换为中文文案，
   迁移时保留组件结构不重排——后续若全站 i18n 立项再回补。
6. **ARTEX 未记录版本（0.3.19-0.3.27）**：本方案基于 0.3.29 终态源码，不受 changelog 空缺
   影响；但 RuoJi6/ARTEX 的 git 历史里有逐票 commit message，遇到语义不明处可 clone 查看
   （本机需走代理）。
